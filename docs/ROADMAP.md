# Photo Layout — дорожная карта реализации

Дата анализа: 4 ноября 2026 года.

Статус: план подготовлен; функции приложения ещё не реализованы.

Основание: предоставленное ТЗ «Photo Layout — React + Vite + TypeScript» и анализ текущих файлов проекта. Этот документ определяет порядок работ, решения для неоднозначных требований и проверяемые условия готовности первой версии.

## 1. Результат первой версии

Локальное SPA для подготовки фотографий к домашней печати. Пользователь добавляет фотографии, выбирает бумагу и один из двух режимов, проверяет автоматически рассчитанные страницы и открывает системный диалог печати.

Приоритеты: физические размеры → корректность и эффективность раскладки → минимум действий → простота поддержки.

В первую версию входят:

- Загрузка нескольких файлов через выбор и drag-and-drop, миниатюры и удаление.
- Пять форматов бумаги, автоматический выбор ориентации, поля 5 мм и зазор 3 мм.
- Режим заданного размера отпечатка и режим количества фотографий на листе от 1 до 12.
- Независимый поворот фотографий на 90° при включённом Auto Rotate.
- Несколько страниц, навигация, автоматический пересчёт и печать всех страниц.
- Чистый TypeScript-модуль раскладки и тесты его геометрических инвариантов.

За рамками версии: сервер, загрузка файлов в сторонние сервисы, Electron, ручное позиционирование, шаблоны, кадрирование, ретушь, экспорт PDF собственным генератором, сохранение проектов, Redux, Tailwind и тяжёлые UI-библиотеки. Canvas не используется для растеризации листа. Service Worker и установочный PWA-режим не требуются: локальность означает обработку файлов в браузере без отправки на сервер.

## 3. Решения, принятые для планирования

Эти решения закрывают неоднозначности ТЗ и служат исходным контрактом реализации.

### Бумага и единицы

- Все расчёты и результат алгоритма — в миллиметрах; масштаб предпросмотра не участвует в расчёте.
- Форматы строго по ТЗ: A4 — 210 × 297, A3 — 297 × 420, A5 — 148 × 210, Letter — 216 × 279, 10 × 15 см — 100 × 150 мм. Для Letter сохраняются размеры из ТЗ, без скрытой подмены более точными стандартными значениями.
- По умолчанию: A4, режим размера 100 × 150 мм, Auto Rotate включён. При первом переходе в режим количества — 4 фотографии на лист.
- Поля 5 мм и зазор 3 мм задаются константами. Дополнительные контролы для них не нужны.
- Выбирать одну ориентацию бумаги для всей печатной задачи, сравнивая раскладку всех фотографий в обоих вариантах. Это позволяет задать один размер `@page`.
- При равной оценке применять стабильное правило выбора: меньше поворотов, затем портретная ориентация бумаги.

### Режим A: заданный размер

- Введённые стороны определяют физический размер слота. Для 100 × 150 мм исходная вертикальная фотография получает слот 100 × 150, горизонтальная — 150 × 100 мм. Для квадратного исходника сохраняется порядок введённых сторон.
- Соответствие длинной стороны слота исходной ориентации не является поворотом изображения: при Auto Rotate = off угол всегда 0°. При Auto Rotate = on разрешён дополнительный поворот конкретного изображения на 90° с перестановкой сторон его слота.
- Изображение целиком вписывается в слот через `contain`. Различие пропорций даёт белое пространство внутри слота, без обрезки и искажения.
- Слоты не уменьшаются ради размещения. Если хотя бы один не помещается ни в одном допустимом варианте, вернуть явную ошибку и заблокировать печать, без частичной потери фотографий.
- Главный критерий выбора — минимальное найденное количество страниц. Глобальный математический оптимум эвристикой не гарантируется.

### Режим B: количество фотографий

- N — целое число от 1 до 12. Каждая полная страница содержит ровно N фотографий, последняя — остаток. Если фотографий меньше N, печатаются только выбранные, без дублирования.
- Сначала разбить исходный список на последовательные группы по N. Внутри группы алгоритм может менять порядок размещения для более плотной упаковки.
- Чтобы «максимальный размер» имел однозначный смысл для разных пропорций, использовать общую длину длинной стороны L. Для пропорции r = width / height размеры равны `(L, L / r)` при r ≥ 1 и `(L × r, L)` при r < 1.
- Найти наибольшее практически найденное L, при котором размещаются все группы. Длина L одинакова для всей задачи; последняя неполная страница не увеличивает фотографии автоматически.
- Ориентацию бумаги выбирать по большему допустимому L. Auto Rotate управляет поворотами отдельных изображений, пропорции всегда сохраняются.

### Файлы и состояние

- Базовые форматы: JPEG, PNG, WebP, если файл успешно декодируется браузером. Неподдерживаемые и повреждённые файлы получают понятное сообщение; остальные продолжают загружаться.
- Исходные пропорции определяются после декодирования с учётом отображаемой ориентации JPEG/EXIF. Не применять EXIF-поворот повторно поверх уже учтённого браузером.
- Каждому добавлению присваивается собственный ID: повторный выбор одного файла является отдельным экземпляром. Проверка отсутствия дубликатов в раскладке выполняется по этим ID.
- Порядок добавления сохраняется независимо от порядка завершения асинхронного декодирования.
- Файлы и настройки живут в памяти вкладки. Сохранение после перезагрузки не входит в версию.

## 4. Архитектура

```text
src/
  App.tsx                         # сборка экрана и состояние настроек
  App.css                         # раскладка интерфейса
  index.css                       # базовые стили
  types/
    photo.ts                      # модель загруженного файла
    layout.ts                     # вход/выход чистого алгоритма
  constants/
    paper.ts                      # размеры бумаги, поля, зазор
  layout/
    geometry.ts                   # границы, зазоры, допуски
    pack.ts                       # упаковка прямоугольников
    calculateLayout.ts            # режимы и выбор ориентации
    calculateLayout.test.ts        # сценарии и инварианты
  hooks/
    usePhotos.ts                  # загрузка, декодирование, очистка URL
  components/
    SettingsPanel.tsx             # бумага, режим, параметры, Auto Rotate
    PhotoUploader.tsx             # input и drop zone
    PhotoList.tsx                 # миниатюры и удаление
    Preview.tsx                   # масштаб и навигация
    Sheet.tsx                     # единый рендерер листа
    PrintArea.tsx                 # все листы и готовность к печати
  styles/
    print.css                     # печатные правила
```

Это целевая структура, а не требование создавать пустые файлы заранее. Небольшие вспомогательные функции можно оставить рядом с потребителем.

Контракт `calculateLayout`:

- Вход: размеры бумаги, массив `{ id, widthPx, heightPx }`, режим и его параметры, `autoRotate`, поля и зазор.
- Выход при успехе: выбранная ориентация, физические размеры листа и массив страниц с прямоугольниками `{ photoId, x, y, width, height, rotation: 0 | 90 }`.
- Выход при ошибке: типизированная причина, например некорректные параметры или слишком большой слот. Пустой список фотографий — успешный результат с нулём страниц.
- `x` и `y` отсчитываются от верхнего левого угла всего листа, включая поля. Размеры прямоугольника описывают его итоговые границы после поворота.
- Модуль не зависит от React, DOM, файловых URL, текущего времени и случайных чисел, не изменяет входные объекты.

Один результат расчёта передаётся и в preview, и в print. `Sheet` отвечает за позиции, физические размеры, вписывание и поворот. Предпросмотр масштабирует целый лист внешней обёрткой; печать использует исходные миллиметры. Для поворота на 90° внутренний контейнер имеет переставленные размеры и вращается вокруг центра, оставаясь внутри рассчитанного слота.

## 5. Этапы реализации

### Этап 1. Контракты, геометрия и ранняя проверка печати

Зависимости: нет.

- [ ] Удалить демонстрационный интерфейс; подготовить основу экрана без декоративных эффектов.
- [ ] Описать типы входа, результата, ошибок и константы бумаги.
- [ ] Реализовать валидацию положительных конечных размеров и целого N в диапазоне 1–12.
- [ ] Добавить Vitest и команды `test` / `test:watch`; начать с тестов геометрии и пустого ввода.
- [ ] Создать минимальный `Sheet` и печатные стили; временно проверить лист с известным прямоугольником 100 × 150 мм и второй страницей.
- [ ] Проверить выбор размеров через динамический `@page`, отсутствие лишней страницы и влияние базовых стилей приложения на печать.

Готово, когда: контракты согласованы в коде, стартовые тесты проходят, пробная печать/PDF сохраняет заданный размер листа и прямоугольника. Временная проверочная разметка не остаётся отдельной функцией продукта.

### Этап 2. Полный алгоритм раскладки

Зависимости: этап 1.

- [ ] Реализовать компактную упаковку, например MaxRects с детерминированным выбором свободного прямоугольника.
- [ ] Корректно учитывать поля и зазор. При использовании виртуальных прямоугольников с добавленным зазором не терять полезную полосу у внешнего края листа.
- [ ] Для каждого изображения рассматривать 0° и, при разрешении, 90°; поддержать смешанные ориентации на одной странице.
- [ ] В режиме A упаковывать все слоты с переносом остатка на следующие страницы, без изменения физических размеров.
- [ ] Пробовать небольшой фиксированный набор стратегий порядка, например исходный порядок, убывание площади и длинной стороны; фиксировать tie-break по исходному индексу.
- [ ] В режиме B подбирать общую длину L с ограниченным числом проб и точностью до 0,1 мм; проверять каждую группу из N фотографий.
- [ ] Всегда сохранять лучший фактически допустимый результат. Не трактовать отказ эвристики как доказательство невозможности упаковки; не обещать точного глобального максимума.
- [ ] Сравнить две ориентации бумаги по критериям выбранного режима и применить стабильные правила при равенстве.
- [ ] Исключить бесконечный цикл создания страниц, если отдельный слот не помещается.
- [ ] Покрыть алгоритм основными сценариями и общими геометрическими инвариантами из раздела 6.

Готово, когда: оба режима работают на смешанных наборах, все фото распределены ровно один раз, нет пересечений и выхода за поля, повторный расчёт даёт идентичный результат. Известные простые случаи подтверждают, что алгоритм действительно использует доступное место.

### Этап 3. Загрузка и полный пользовательский сценарий

Зависимости: этап 2.

- [ ] Реализовать единый путь обработки файлов из `input multiple` и drag-and-drop.
- [ ] Добавить декодирование, стабильные ID, метаданные, миниатюры и удаление отдельного экземпляра.
- [ ] Управлять `URL.createObjectURL` / `URL.revokeObjectURL`: освобождать URL после удаления и размонтирования; не отзывать используемые оригиналы до печати.
- [ ] Обработать гонки: удаление или размонтирование во время декодирования не возвращает файл в список и не оставляет утечку URL; поведение устойчиво в React StrictMode.
- [ ] Собрать правую панель: формат, переключатель режима, два размера или N, Auto Rotate, кнопка Print.
- [ ] Сохранять введённые значения обоих режимов при переключении; не передавать пустые и невалидные значения в расчёт.
- [ ] Собрать левую область: лист в правильных пропорциях, масштаб по доступной области, номер страницы и переключение.
- [ ] При изменении параметров пересчитывать раскладку; после удаления фото ограничивать индекс текущей страницы новым диапазоном.
- [ ] Добавить состояния: нет фотографий, загрузка, ошибка файла, ошибка параметров, невозможность размещения.
- [ ] Обеспечить подписи контролов, видимый focus, управление с клавиатуры и текстовое пояснение ошибок. На узком экране расположить области вертикально.

Готово, когда: пользователь может пройти путь от загрузки до просмотра всех страниц в обоих режимах без ручной раскладки. Ошибка отдельного файла не ломает остальные; очистка списка возвращает пустое состояние.

### Этап 4. Печать оригиналов и совпадение с предпросмотром

Зависимости: этап 3; использовать печатную основу этапа 1.

- [ ] Отрисовать в `PrintArea` все страницы тем же `Sheet`, который используется для предпросмотра.
- [ ] Использовать URL оригинальных файлов, без замены на уменьшенные миниатюры.
- [ ] Перед `window.print()` дождаться декодирования изображений печатной области; при ошибке показать причину и не запускать неполную печать.
- [ ] В `@media print` скрыть интерфейс и обнулить внешние отступы, экранные ограничения ширины, тени и масштабирование контейнеров.
- [ ] Задать `@page { size: <width>mm <height>mm; margin: 0; }` из результата раскладки, размеры листов и слотов — в `mm`.
- [ ] Установить запрет разрыва внутри листа и разрыв между листами без принудительного разрыва после последнего.
- [ ] Убедиться, что при отмене диалога сохраняются фотографии, настройки и текущая страница.
- [ ] Добавить краткую подсказку рядом с печатью: выбрать совпадающую бумагу, масштаб 100% / фактический размер, проверить поля и отключить колонтитулы в системном диалоге.

Готово, когда: печатаются все рассчитанные страницы с оригинальными изображениями; позиции, размеры, повороты и белые поля совпадают с предпросмотром, интерфейс и лишние листы отсутствуют.

Приложение управляет HTML/CSS, но не может принудительно установить настройки диалога, драйвера и аппаратные поля принтера. Проверять отдельно геометрию документа и физический отпечаток; результат измерения фиксировать вместе с настройками печати.

## 6. Проверки и критерии приёмки

### Автоматические тесты чистого алгоритма

| Сценарий | Проверяемый результат |
| --- | --- |
| Пустой список | Ноль страниц, нет ошибки и фиктивного отпечатка |
| Два отпечатка 100 × 150 мм на A4 | Одна страница, физические стороны каждого слота 100 и 150 мм |
| Две вертикальные и одна горизонтальная фотографии | Все размещены, исходные пропорции сохранены, проверены смешанные слоты на одной странице, где это допустимо |
| Auto Rotate выключен | У всех прямоугольников `rotation = 0`; исходная ориентация изображения сохраняется |
| Auto Rotate включён | Есть фиксированный пример, в котором индивидуальный поворот улучшает найденную раскладку; остальные фото не обязаны поворачиваться |
| Десять отпечатков 100 × 150 мм на A4 | Несколько страниц, все десять ID встречаются ровно один раз |
| N = 1, 4 и 12 | На полной странице ровно N фотографий, на последней только остаток |
| 10 фотографий, N = 4 | Страницы с 4, 4 и 2 фото, общая длина L одинакова |
| Выбрано меньше N фотографий | Одна неполная страница без копирования файлов |
| Пропорции исходника отличаются от слота | Размер слота не меняется; вписывание изображения проверяется отдельно в рендерере |
| Слот больше доступной области | Типизированная ошибка, нет зависания и бесконечной пагинации |
| Нули, отрицательные размеры, NaN, Infinity, дробное/выходящее за диапазон N | Управляемая ошибка валидации |
| A3, A5, Letter, 100 × 150 мм | Физические размеры, поля и ограничения соответствуют выбранной бумаге |
| Повторный расчёт одного ввода | Полное совпадение результата, исходный массив не изменён |

Для каждого успешного непустого результата проверять общие инварианты:

1. Все координаты и размеры конечны, ширина и высота положительны.
2. Прямоугольники находятся внутри области `[margin, paperSize − margin]`.
3. Любая пара слотов разделена по горизонтали или вертикали зазором не меньше 3 мм с числовым допуском `epsilon = 1e-6 мм`.
4. Каждый входной ID присутствует ровно один раз, лишних ID нет.
5. Повороты принадлежат множеству {0°, 90°} и соответствуют Auto Rotate.
6. В режиме A сохраняются введённые стороны слота с допустимой перестановкой; в режиме B сохраняются пропорции и лимит N.

Добавить небольшой воспроизводимый набор сгенерированных пропорций с фиксированным seed для проверки инвариантов. Не проверять только конкретные координаты, если требование относится к свойствам раскладки.

### Проверка интерфейса и файлов вручную

- Выбор нескольких файлов, drop, повторный выбор того же файла и удаление во время загрузки.
- JPEG с EXIF-ориентацией, PNG с прозрачностью, WebP, повреждённый и неподдерживаемый файл.
- Быстрое переключение бумаги, режима и Auto Rotate; временно пустое числовое поле.
- Удаление последнего фото на последней странице, удаление всех фото, повторная загрузка.
- Клавиатурный доступ к загрузке, удалению, переключению страниц и печати.
- Кнопка Print недоступна без готовой корректной раскладки и во время подготовки файлов к печати.

### Проверка печати вручную

Проверить в доступных актуальных Chrome/Chromium и Firefox; записать фактические версии и результат. Матрица является планом проверки, а не заявлением уже подтверждённой совместимости.

| Проверка | Критерий |
| --- | --- |
| Одна и несколько страниц | Число листов равно результату алгоритма, последнего пустого листа нет |
| Оба направления бумаги и все пять форматов | Размер страницы в диалоге/PDF соответствует результату расчёта; ограничения браузера зафиксированы |
| Смешанные ориентации и `contain` | Те же повороты и белые области, что в preview; нет обрезки |
| Качество | Печать использует оригинал, миниатюры не подставляются |
| Масштаб документа | В PDF при масштабе 100% слот 100 × 150 мм сохраняет эти размеры в пределах точности измерения |
| Физический отпечаток | На доступном принтере измерить контрольный слот; целевой допуск ±1 мм при масштабе 100%, отклонения исследовать с учётом драйвера |
| Интерфейс и диалог | Панель, навигация и кнопки не печатаются; колонтитулы отключаются настройкой браузера |
| Отмена печати | Приложение остаётся работоспособным, повторная печать возможна |

Если принтер недоступен, отметить физическую проверку как невыполненную. Сохранение PDF подтверждает геометрию документа, но не заменяет проверку бумажного отпечатка.

## 7. Основные риски и порядок их снятия

| Риск | Как снизить | Когда проверить |
| --- | --- | --- |
| CSS или диалог меняет физический размер | Ранний печатный прототип, миллиметры, сброс экранных стилей, измерение PDF и отпечатка | Этапы 1 и 4 |
| Эвристика плохо размещает смешанные фото | Несколько стабильных стратегий упаковки, сравнение двух ориентаций, известные контрольные примеры | Этап 2 |
| Поворот в DOM не совпадает с геометрией | Один `Sheet`, явные итоговые границы и центр вращения | Этапы 1–4 |
| Файлы декодируются в другом порядке или повторно учитывается EXIF | Стабильные ID и порядок, реальные EXIF-примеры, единая обработка метаданных | Этап 3 |
| Большие файлы и утечки памяти | Object URL, корректная очистка, отсутствие полноразмерных копий листа; ручная проверка набора из 50 фото | Этапы 3 и 5 |
| Пересчёт блокирует интерфейс | Ограничить число стратегий и проб размера, измерить набор 50 фото; усложнять исполнение только при подтверждённой проблеме | Этапы 2 и 5 |
