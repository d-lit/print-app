# Photo Layout

Локальное приложение для подготовки фотографий к домашней печати. Добавьте снимки, выберите бумагу и параметры — приложение рассчитает раскладку, страницы и ориентацию листа.

React + TypeScript + Vite, обычный CSS. Фотографии обрабатываются в памяти вкладки; приложение не отправляет их на сервер, не использует внешние сервисы, шрифты или UI-библиотеки.

## Запуск

Нужны Node.js 24+ и Yarn 1.22+.

```sh
yarn install --frozen-lockfile
yarn dev
```

Откройте адрес, который выведет Vite, обычно `http://localhost:5173`. Используйте локальный сервер, а не открытие `index.html` через `file://`.

```sh
yarn test          # 52 теста: размеры, вписывание, раскладка, зазоры и метки реза
yarn test:watch    # пересчёт тестов при изменении файлов
yarn lint         # Oxlint
yarn build        # проверка TypeScript и сборка в dist/
yarn preview      # локальная проверка production-сборки
```

Тесты используют встроенные возможности Node.js и запускаются без дополнительного тестового фреймворка. Runtime-зависимости — только React и React DOM.

## Рабочее окно

На desktop приложение занимает всю ширину и высоту окна: список фотографий слева, предпросмотр по центру, параметры печати справа. Обе боковые панели заполняют рабочую высоту под шапкой и прокручиваются независимо. Кнопка печати закреплена снизу справа и остаётся доступной при длинном списке настроек. На узких экранах блоки располагаются вертикально.

Заголовки панелей и футеры файлов/предпросмотра имеют общую высоту 56 px. Основной текст увеличен до 14 px, подписи и подсказки — не мельче 13 px; используются тёмные контрастные оттенки.

## Как пользоваться

1. Добавьте JPEG, PNG или WebP кнопкой или перетащите несколько файлов в область загрузки. Удаление работает и во время чтения файлов. Повреждённый или неподдерживаемый файл не мешает загрузке остальных.
2. Выберите A4, A3, A5, Letter или фотобумагу 100 × 150 мм. Технологические поля — 5 мм. Зазор по умолчанию 3 мм, его можно изменить, включая 0 мм.
3. Выберите режим: физический размер отпечатка либо количество фотографий на листе от 1 до 12.
4. При необходимости измените порядок файлов стрелками вверх/вниз возле снимков. Порядок сохраняется после чтения файлов, удаления или добавления новых. Затем просмотрите листы стрелками под предпросмотром.
5. Нажмите «Печатать фотографии». Печатаются все рассчитанные страницы, а не только текущая.

После ручного перемещения алгоритм учитывает выбранную очередность при распределении фото по страницам, в том числе в «Плотно» и режиме количества. Очистка списка сбрасывает ручную очередность. Во время подготовки печати перемещение заблокировано.

Настройки и фотографии не сохраняются после перезагрузки страницы. Повторное добавление одного файла создаёт отдельный экземпляр для печати.

## Два режима

**Размер фото.** Выберите физические стороны и способ вписывания в селекте «Как вписать изображение»:

| Способ | Поведение при несовпадении пропорций |
| --- | --- |
| Весь кадр · с белыми полями | Точный заданный размер, например 100 × 150 мм. Изображение целиком, свободное место заполнено белым. Метки показывают весь отпечаток вместе с добавленными полями. Это режим по умолчанию. |
| Точный размер · обрезать края | Точные 100 × 150 мм без добавленных полей. Кадр заполняет формат через `object-fit: cover`, лишние края обрезаются по центру. Метки идут по заданному размеру. |
| Весь кадр · без полей | Введённые стороны задают максимальный формат. Отпечаток сохраняет исходные пропорции: например, источник 3:4 впишется как 100 × 133,3 мм. Ни кадрирования, ни добавленных полей; метки идут по реальному размеру файла на листе. Размер первого отпечатка показан под селектом. |

Белый или прозрачный фон внутри исходного файла считается частью изображения. Приложение не ищет границы цветного рисунка и не удаляет белый фон автоматически. В режиме обрезки кадрируется выбранный прямоугольник исходника, в остальных двух режимах файл сохраняется целиком. Изображения не растягиваются непропорционально.

Способ размещения выбирается отдельно:

- **Под резак** — по умолчанию. Ячейки выстроены в ровную сетку, центрированную на листе. Их координаты сохраняются на всех страницах, включая последнюю неполную. При точном размере линии реза совпадают и листы можно совмещать для резки стопкой. Для 17 вертикальных снимков с отпечатками 100 × 150 мм выбирается альбомный A4 с двумя вертикальными отпечатками рядом, всего 9 листов.
- **Плотно** — упаковка со смешанной ориентацией ячеек. Изображения выровнены по верхнему левому краю своих ячеек, без дополнительного сдвига из-за центрирования. В режиме «без полей» упаковщик использует реальные размеры изображений, без невидимых белых прямоугольников. Может экономить бумагу, но линии реза различаются.

В режиме «без полей» сетка рассчитывается по реальным габаритам отпечатков. Если пропорции файлов различаются, их конечные размеры и отдельные границы реза тоже различаются. Масштаб снимков не уменьшается ради дополнительного количества на листе. Слишком большой отпечаток вызывает ошибку.

**Фото на листе.** Полная страница содержит ровно выбранное N, последняя — остаток. Входной список разбивается на последовательные группы по N, положение фото внутри группы подбирается автоматически. Алгоритм увеличивает общую длину длинной стороны снимков, сохраняя их исходные пропорции. Длина одинакова на всех страницах; последняя неполная страница не увеличивается отдельно. Если фото меньше N, создаётся одна неполная страница без дубликатов.

**Auto Rotate.** По умолчанию включён: алгоритм может независимо повернуть снимок на 90°. В сетке выбирается более полное вписывание; для обрезки это также помогает сохранить больше исходного кадра. При выключении угол каждого изображения равен 0°. Ориентация самой бумаги выбирается автоматически для всей задачи.

## Отступы и метки реза

В секции «Отступы и резка» доступны:

- **Зазор между отпечатками** в миллиметрах, включая 0. Есть быстрый выбор 0, 5 и 10 мм. Параметр применяется в обоих режимах компоновки, учитывается в пагинации и показан под предпросмотром. Пустое или отрицательное значение блокирует печать до исправления.
- **Метки реза** — включение и выключение одновременно для preview и print. Отключение не меняет геометрию отпечатков.
- **Вид метки реза**: «Уголки» с лучами длиной 3 мм снаружи отпечатка или «Пунктирная линия» по его полному периметру. Пунктир полезен для принтов с белым фоном. Общие границы при нулевом зазоре объединяются, чтобы не печатать пунктир дважды. Если увеличенному уголку не хватает места у края листа или соседнего фото, его луч укорачивается, сохраняя линию реза и не заходя на изображение.

Метки следуют границе готового отпечатка согласно способу вписывания. В режиме с полями добавленные белые области входят в его размер; в режиме без полей метки показывают края всего исходного файла. Настройки доступны для сетки, плотной упаковки и режима количества.

Поле 5 мм от края бумаги сохраняется для домашнего принтера. Например, точный отпечаток 100 × 150 мм не помещается на одноимённой бумаге с этими полями: выберите больший лист или меньший размер.

## Печать в реальном размере

- Выберите в диалоге ту же бумагу, что в приложении, и соответствующую ориентацию.
- Установите **100% / фактический размер**, отключите «подогнать под страницу» и колонтитулы.
- Проверьте поля и доступную область печати принтера. CSS-поля документа равны нулю; технологические отступы уже учтены раскладкой.
- Приложение ждёт декодирования оригиналов перед вызовом `window.print()`.

Предпросмотр и печатная область используют один компонент `Sheet` и один результат расчёта. Печать идёт из исходных файлов с размерами и координатами в миллиметрах, без растеризации всего листа в Canvas.

Браузер, драйвер и принтер могут менять масштаб и физические поля. Результаты программной проверки и оставшиеся ручные проверки описаны в [docs/QA.md](docs/QA.md). Физическая печать на принтере пока не проверена.

## Архитектура

- `src/layout/` — чистый расчёт: регулярная сетка под резак, MaxRects для плотной упаковки и режима количества, сравнение ориентаций, геометрия вписывания и меток, проверка ввода и тесты.
- `src/types/`, `src/constants/` — типы и форматы бумаги.
- `src/hooks/usePhotos.ts` — чтение файлов, метаданные с отображаемой EXIF-ориентацией, жизненный цикл object URL; одновременно декодируется до четырёх файлов из одной загрузки.
- `src/components/` — настройки, загрузка, список фото, предпросмотр, единый лист и печатная область.
- `src/styles/print.css` — правила печати; динамический размер `@page` задаётся в `App.tsx`.

При автоматической очередности упаковка проверяет несколько стабильных порядков и варианты с поворотом и без. После ручной сортировки сохраняется выбранная последовательность, а заполнение свободного места более поздними фотографиями перед текущей не используется. В режиме количества размер подбирается с шагом 0,1 мм; сохраняются только фактически допустимые раскладки. Алгоритм детерминирован и практически эффективен, но не гарантирует глобального математического оптимума.

Letter реализован в размерах из исходного ТЗ: 216 × 279 мм. Не поддерживаемые браузером форматы изображений, включая HEIC, нужно заранее преобразовать в JPEG/PNG/WebP.
